## 自动化覆盖

- TypeScript 类型检查与生产构建。
- Node 内置测试运行器 + jsdom：URL 匹配、AST 检查、响应解析、幂等初始化、版本清理、SPA 路由、单脚本异常隔离、上下文隐私过滤与长度限制。

- 在 HTTP 边界替换 AI 响应，验证生成成功、429 失败保留旧版本、请求取消和 Key 不返回给用户脚本。此测试不代表真实模型生成质量。
- 固定示例脚本验证动态代码块增加复制按钮、表格 CSV 下载；截图覆盖 320px、390px、1024px，检查横向溢出。

## 测试环境的特殊处理

无头 Chromium 无法点击原生可选主机权限弹窗。端到端测试复制构建结果到一次性目录，仅在测试副本中预授权 `http://127.0.0.1/*`。正式 `dist/manifest.json` 不包含该预授权；其网站权限仍由用户按需授予。

测试使用临时浏览器配置，不读取用户已有 Chrome 登录信息。AI 测试密钥是无效占位值，未调用真实服务。新增四家请求与响应契约、旧配置迁移、Key 隔离及全量脱敏测试；Chromium 中模拟 DeepSeek / Gemini / Claude 连接测试，保留 OpenAI 模拟生成、取消和失败回归。真实模型可用性、网络及计费需要用户自己的 Key 进行连接测试。

## 仍需人工或外部验证

1. 在普通 Chrome 中验证原生站点权限弹窗、从工具栏打开侧边栏，以及元素选择交互。
2. 用户配置真实 Key 和模型后，验收隐藏侧栏、复制代码、导出表格三类自然语言请求的生成质量。
3. 实际断网、余额不足、4 分钟总超时，以及浏览器回收 service worker 的恢复体验。
4. Chrome 138 最低版本与 Edge 兼容性；自动化测试使用较新 Chromium，不能代表所有版本。
5. 扩展商店对 AI 生成用户脚本的审核适用性、运营主体和最终隐私材料。

已知限制：任意脚本的静态检查不完备；同步死循环不能由 try/catch 中断；多个改造对同一元素可能冲突；跨域 iframe、浏览器内部页及 PDF 查看器不支持。浏览器关闭或权限撤销后，无法保证每个 DOM 修改即时清理，必要时刷新网页。
