# PageCraft 产品需求文档

2026-10-28 自动启动扩展：自建工具支持版本化的自动启动开关、全站/指定网址范围、可选 SPA 路由重初始化。旧数据默认手动；全站授权必须用户确认。自动实例常驻，停用、删除、更新及离开范围时清理；初始化返回值不进入侧边栏结果。此项替代下文“工具不会自动运行”的旧限制，详见 CUSTOM_TOOLS.md。

新增自建工具范围（2026-10-27）：自然语言生成或手动编写异步 JavaScript；生成、试运行、保存分别操作，不自动执行生成结果。工具全局可用，无站点规则；支持 JSON 参数、文本/表格/图片/文本文件结果、内置工具组合、取消、删除及最近 10 个版本回退。保存在本地扩展存储，重启后恢复；不会随网页加载自动运行。接口与边界见 [CUSTOM_TOOLS.md](CUSTOM_TOOLS.md)。

新增通用工具范围：独立工具页，提供可视区域截图、整页滚动拼接截图和页面文本提取；无需 URL 规则或 AI Key。支持当前标签页检查、进度、取消、预览及下载，执行完恢复页面。实现边界与验收见 TOOLS.md。

> 当前开发模式（优先于下文旧版安全设计）：已移除生成代码的 API、标签、属性、动态访问、CSS 及代码长度限制，并放宽 USER_SCRIPT CSP。只检查 JavaScript 语法、返回数据结构和非空结果。任意生成代码可能读取页面数据、联网或产生不可撤销副作用，仅用于测试网页。API Key 隔离、站点授权、浏览器自身限制、任务取消和版本管理仍保留。下文原有静态安全检查描述不再代表当前实现。

## 1. 产品定位

**让每个网页，都按你的方式工作。**

PageCraft（页匠）是一款 AI 网页定制扩展。用户描述想增加或修改的功能，系统结合当前页面结构生成 JavaScript/CSS，保存为一个“改造”，自动应用到用户指定的网站或页面。

目标用户是经常使用网页办公工具、阅读网站和数据列表，希望减少重复操作但不会编写脚本的人。高级用户可以查看、编辑脚本和匹配规则。

核心闭环：描述需求 → 获取必要页面上下文 → 生成并校验 → 立即应用 → 本地保存 → 下次访问自动运行。

成功标准：用户无需编辑代码即可完成一个常见网页改造；刷新或重启浏览器后仍生效；可以明确关闭、恢复旧版本和定位失败原因。保存后的正常运行不再调用模型。

## 2. 典型场景与范围

| 场景 | 用户输入示例 | 预期结果 |
| --- | --- | --- |
| 阅读定制 | 隐藏右侧推荐栏，把正文加宽 | 当前页立即改变，匹配页面自动应用 |
| 表格增强 | 给这个表格增加导出 CSV 按钮 | 增加按钮，点击导出当前已加载数据 |
| 列表过滤 | 给列表加个关键词筛选框 | 新增输入框，筛选当前已加载条目 |
| 操作便利 | 为每段代码增加复制按钮 | 已有及后续加载的代码块均可复制 |
| 持续修改 | 把刚才的按钮移到表格上方 | 生成新版本，保留旧版本供回退 |

MVP 包含：中文自然语言交互、页面上下文采集、OpenAI / DeepSeek / Google Gemini / Claude 接入、生成与修订、脚本检查、立即执行、URL 匹配、本地持久化、改造管理、错误反馈和版本回退。

MVP 不包含：账号与云同步、脚本市场、付费订阅、自定义代理端点、跨站自主任务、后台定时操作、自动登录/付款/提交表单、绕过访问限制。导出只覆盖页面已加载的数据，不承诺抓取整个站点。

## 3. 用户流程与界面

### 3.1 首次使用

安装扩展后进入设置页，选择服务商，填写对应 API Key 和模型 ID。各服务商独立保存 Key、模型和发送授权，旧 OpenAI 配置自动迁移。模型必须支持对应 JSON 输出能力；不硬编码“永远最新”的模型。提供连接测试及清除当前服务商 Key 操作，测试可能产生少量 API 费用，结果不展示密钥。

用户在扩展详情中开启浏览器要求的“允许用户脚本”。首次访问目标网站时按需授权站点访问。未授权时可保留需求草稿，但不能采集页面或执行脚本。

### 3.2 创建改造

1. 点击扩展图标打开侧边栏，展示当前网站、需求输入框及该网站已有改造。
2. 默认匹配当前源下所有路径，用户可改为当前路径或自定义 Chrome match patterns；生成前始终可见。
3. 点击“生成并应用”，采集当前页必要结构，并将需求及上下文发送给已保存的服务商。首次发送前说明页面片段将发送至用户选定的 AI 服务。
4. 模型返回名称、说明及脚本；匹配范围由用户决定，模型不能扩大授权范围。
5. 解析、语法检查和风险检查通过后，自动保存版本并立即尝试应用，无额外逐次预览确认。
6. 展示生成、校验、保存、执行状态；区分“执行无异常”和“功能已达到预期”，不把未验证的结果标为成功。
7. 用户可以继续描述调整要求、查看源码或禁用该改造。

### 3.3 管理与恢复

管理页提供全部改造的搜索、站点筛选、启用/禁用、匹配规则编辑、源码编辑、删除、版本回退和最近运行错误。源码手工编辑同样经过校验。

更新生成失败时保留已生效的旧版本。每项保留最近 10 个版本；回退须重新校验和注册。删除提供短时撤销，撤销期结束后清除该项数据。

禁用和删除立即取消后续自动执行；运行时尝试清理当前页样式、节点、监听器和观察器。任意 DOM 修改无法保证完全逆转，清理不完整时明确提示刷新恢复。更换版本优先清理旧版本，无法干净清理则要求刷新，避免叠加执行。

### 3.4 界面组成

- 侧边栏：当前站点、需求对话、匹配范围、任务进度、改造列表、错误与修复入口。
- 管理页：改造详情、源码、匹配规则、版本记录、最近错误。
- 设置页：Key、模型 ID、连接测试、页面上下文说明、清除本地数据。

界面使用中文，以“改造”作为用户可见名称；源码等高级选项不干扰主流程。未保存需求按标签页保留，切换页面时重新确认上下文来源；关闭侧边栏不能导致已保存改造丢失。

## 4. 功能要求

### 页面上下文

仅采集当前顶层页面中与任务有关的 DOM 结构、标签、可访问名称和有限文本。提供元素选择能力，让用户缩小目标范围；默认结构摘要不包含输入框值、密码、Cookie、网页存储内容、隐藏字段或完整 HTML。URL 去除查询参数和 fragment 后作为默认上下文。

上下文默认上限 20,000 字符，超限按选中区域优先裁剪并提示。普通可见文本也可能含个人信息，因此允许查看待发送摘要；不声称脱敏能发现全部敏感数据。网页文本只作为数据，不能覆盖扩展的生成指令或授权范围。

### 生成与修复

要求返回严格结构化结果：名称、功能说明、JavaScript 源码、可选 CSS 和可人工检查的验证步骤。结果不合法、语法错误或风险规则命中时拒绝执行，显示具体原因并允许重试。MVP 不无限自动修复；用户点击修复后发起新请求。

生成任务使用流式响应，显示已接收字符数；总超时为 4 分钟，支持取消。区分用户取消、总超时、连接断开和模型输出长度耗尽；取消、截断或较旧请求的迟到结果不得覆盖新结果。处理 Key 无效、无模型访问权、限流、断网、余额相关错误和拒绝生成，保留用户需求。不自动重试计费请求。

### 执行与持久化

每个文档中同一改造版本只能初始化一次。脚本采用初始化/清理生命周期，处理动态内容时使用有边界、节流的观察器，不能扫描整页形成高频死循环。

保存的启用脚本在匹配网页加载时自动运行，不依赖侧边栏开启或再次调用 AI。单项异常不阻止其他改造初始化；同步死循环无法仅靠 try/catch 隔离，属于执行层需要记录的限制。

SPA 路由变化后重新判断完整当前 URL，必要时清理或应用；顶层页面优先，跨域 iframe、浏览器内部页、扩展商店页面和内置 PDF 查看器不在 MVP 支持范围。

浏览器重启、扩展更新后核对保存数据与脚本注册状态，修复缺失或过期注册。站点权限被撤销时停止对应执行，保留改造并显示缺少权限。

### URL 规则

采用 Chrome match patterns，支持 include 与 exclude。排除优先，仅支持 HTTP/HTTPS；禁止无意自动扩展为全站访问。match patterns 不提供任意查询参数精确匹配，本版页面规则按源和路径解释。

对新增规则校验语法、展示示例 URL 是否匹配，并在缺少站点授权时请求对应权限。多个匹配改造按创建时间依次初始化；不承诺自动解决它们对相同元素的冲突。

## 5. 技术约束与数据

### 扩展结构

建议 TypeScript + React + Vite。侧边栏负责交互，service worker 负责受信任 API 调用、配置及注册协调，打包的 content script 负责上下文采集，生成脚本在 USER_SCRIPT 隔离世界执行。

**修正早期构想：`chrome.scripting.executeScript` 不能直接把任意生成的字符串当作函数执行。** 动态用户脚本使用 `chrome.userScripts`；打包的静态辅助脚本才使用 scripting。禁止用 eval/new Function 或注入远程 script 标签绕过扩展 CSP。

Chrome 138+ 作为初始目标，启动时探测 userScripts 及所需方法是否可用。注册用于后续导航；当前页即时执行优先使用受支持的 userScripts.execute，缺失时明确要求刷新，不宣称已经即时应用。Edge 经过独立测试再宣布支持。

生成请求由受信任扩展上下文直接发送给所选服务商；Key 不进入 prompt、页面脚本、日志或消息桥。请求生命周期需处理 service worker 中断，重启后将悬挂任务标记为中断而非永久加载。

### 本地数据

| 数据 | 最小内容 |
| --- | --- |
| 设置 | schemaVersion、provider、model、API Key |
| 改造 | id、name、description、matches、excludeMatches、enabled、activeVersionId、createdAt、updatedAt |
| 版本 | id、craftId、需求、script、css、检查结果、createdAt |
| 运行状态 | craftId、versionId、页面源/路径、时间、状态、裁剪后的错误 |

使用 chrome.storage.local，本版无账号同步。Key 本地保存不等于加密保险库；storage 访问限定到受信任扩展上下文。不要永久保存原始页面上下文，错误信息不得包含 Key 或整页内容。检测存储配额错误，保存失败不能报告已保存或覆盖旧版本。

### 安全边界

用户已经选择“检查通过直接应用”。本版采用 AST 静态检查加隔离执行，禁止明显的动态执行、远程代码加载、凭证读取、网络外传及自动敏感提交；不依赖简单关键词正则宣称代码安全。

**任意 JavaScript 的静态扫描不是完备安全保证；USER_SCRIPT 隔离世界也共享页面 DOM。** 绕过检查、通过 DOM 发起网络请求等残余风险必须在实现评估中考虑。若需要严格能力限制，应另行引入受限指令集或解释器，不把该保障作为本版承诺。

页面与生成脚本不得通过桥接消息获得通用扩展 API、API Key 或任意后台网络代理能力。只开放必要的有限状态与清理协议，并校验消息来源和格式。

Chrome Web Store 对动态代码有政策约束。userScripts 是应验证的实现路径，不保证 AI 生成代码必然通过审核；上架前审查功能、隐私披露及当前政策。MVP 先通过本地加载验证。

## 6. 验收标准

使用本地静态阅读页、异步表格页、SPA 页面构成可复现测试集；真实网站仅作为补充测试，不能把站点变化当作固定回归基线。

| 编号 | 测试 | 通过标准 |
| --- | --- | --- |
| A01 | 配置与错误 | Key/模型错误清晰可见；需求不丢失；Key 不进入页面及日志 |
| A02 | 生成闭环 | 隐藏侧栏、增加复制按钮、表格导出三个场景生成后可实际操作 |
| A03 | 持久化 | 刷新、关闭标签页、浏览器重启后，无模型调用自动恢复 |
| A04 | 匹配范围 | 正向/排除规则、不同源、不同路径和 SPA 路由均符合配置 |
| A05 | 动态页面 | 异步新增条目生效；重复运行不产生多个按钮或重复监听 |
| A06 | 生命周期 | 禁用、删除、回退和更新不重复注册；无法清理时提示刷新 |
| A07 | 失败保护 | API 超时、取消、非法 JSON、语法错误、存储失败保留旧版本 |
| A08 | 风险检查 | 明显凭证读取、外传、eval 等样例被拒绝；记录扫描局限 |
| A09 | 上下文 | 表单值、Cookie、隐藏字段不发送；超限裁剪且用户可知 |
| A10 | 环境限制 | 内部页、无站点权限、userScripts 未启用时给出明确状态 |
| A11 | 恢复 | 扩展更新与 worker 重启后注册一致，未完成任务可恢复为错误状态 |

确定性执行层使用固定脚本回归测试；模型生成质量使用独立样例集人工验收，避免把模型随机性混入底层测试。采集生成耗时、生成通过率和运行错误仅用于本地验证，MVP 不默认上传遥测。

## 7. 开发阶段

1. 技术验证：userScripts 注册/执行、允许用户脚本开关、权限、版本清理、重启恢复；确认商店政策适用性并记录结论。
2. 核心 MVP：设置、侧边栏、上下文采集、生成校验、立即应用、自动恢复，完成 A01–A05。
3. 可用性完善：版本、匹配编辑、错误修复、禁用删除、SPA 支持，完成剩余验收。
4. 分发准备：Edge 验证、隐私政策、安装说明及商店材料；是否发布由项目负责人另行决定。

本地开发版已进入实现与验证阶段；真实模型质量、原生授权交互和商店发布仍需按验证记录完成。未创建远程仓库，未发布产品。
