# PageCraft · 页匠

<img src="public/icons/icon-128.png" alt="PageCraft 标志" width="80" height="80">

**用 AI 持久化定制网页，创建可复用的浏览器工具。**

[English](README.md) | 简体中文

PageCraft 是 Chrome Manifest V3 扩展。用自然语言描述需求，生成网页改造
**Craft**，应用并保存后，下次访问匹配网页时自动生效。你也可以用 AI 或
JavaScript 创建工具，手动运行，或在授权网站自动启动。

PageCraft 面向希望按自己的工作方式定制网页的用户，将持久化网页改造与可复用
浏览器工具放在一起。使用自己的 AI 服务商，检查生成代码，把改造与工具保存在浏览器中。

**项目状态：** 早期开发阶段（0.1.0）。仓库包含扩展源码、测试和开发文档，
可按下方步骤从源码安装。PageCraft 采用 [MIT 许可证](LICENSE)开源。
默认 README 使用英文，本文件为中文说明。

[快速开始](#安装使用) · [AI 服务商](#设置与-ai-服务商) · [本地开发](#开发与测试) · [参与贡献](#参与贡献) · [安全报告](#安全报告)

> **开发模式警告：** 当前只检查脚本语法和返回结构，不验证代码安全性。
> 用户脚本 CSP 较宽松，生成或手写的代码可以读取、修改页面数据并联网。
> 请仅在测试网页运行可信代码。取消、停用和版本回退不能撤销所有副作用，
> PageCraft 不是安全沙箱。

## 功能概览

| 模块           | 已实现能力                                                                                   |
| -------------- | -------------------------------------------------------------------------------------------- |
| 网页改造 Craft | 自然语言生成、页面摘要、元素选择、包含/排除规则、保存后自动应用及 SPA 路由处理               |
| 改造管理       | 启用/停用、源码编辑、AI 修订保持名称、最近 10 个版本、回退、删除后 10 秒内撤销               |
| 内置工具       | 可视区域截图、整页截图、预览、下载和取消；无需配置 AI                                        |
| 自建工具       | AI 生成或手写异步 JavaScript、JSON 参数、临时 CSS、试运行、版本记录及文本/表格/图片/文件结果 |
| 自动工具       | 所有网站或指定网站自动启动，可选 SPA 路由变化时重运行，支持生命周期清理                      |
| 运行时 AI      | 自建工具通过 `ctx.ai.ask()` 调用已配置模型，不获取 API Key                                   |
| 使用入口       | 420px Popup、侧边栏和管理页；工具栏记住上次选择的 Popup/侧边栏模式                           |
| 国际化         | 英文、简体中文、跟随浏览器、偏好持久化及多窗口同步                                           |

## 可以用来做什么

- 创建改造，隐藏干扰区域或调整网站的阅读排版。
- 创建可复用工具，将网页链接整理成可下载的表格。
- 添加页面操作，调用已配置的 AI 总结选定内容。
- 创建每次访问指定网站时自动添加控件、停用时清理控件的工具。

这些是需求示例，不是内置预设。生成效果取决于模型和目标网页；开启自动执行前，
请先检查代码并验证效果。

PageCraft 专注于用户主动发起的网页定制与浏览器工具，不是通用跨页面任务代理、
漏洞扫描器或诈骗检测器。入口为扩展弹窗、侧边栏和管理页，不提供网页悬浮入口。

## 安装使用

需要 **Chrome 138+**。本文开发流程使用 **Node.js 22.12+** 和 npm。
下载仓库源码，或使用仓库托管平台提供的地址克隆项目。在项目根目录执行：

```sh
npm ci
npm run build
```

1. 打开 `chrome://extensions`，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择本项目的 `dist/` 目录。
3. 在 PageCraft 扩展详情中开启“允许用户脚本”。
4. 打开普通 HTTP/HTTPS 网页，点击浏览器工具栏中的 PageCraft 图标。
5. 首次打开为 Popup，右上角可切换到侧边栏；选择在浏览器重启后仍保留。

元素选择、交互式工具和长任务建议使用侧边栏。Chrome 原生 Popup 失焦后会关闭；
关闭 Popup 不一定停止后台任务，重新打开也不保证恢复结果或触发下载。

修改代码后需要重新构建，在扩展管理页重新加载扩展，再刷新目标网页。
Edge 尚未完成兼容验证。

## 设置与 AI 服务商

设置页分为“通用设置、AI 配置、脚本执行、本地数据”四个独立区块。

在“AI 配置”选择服务商，填入自己的 API Key 和兼容的模型 ID，阅读并同意数据
发送说明后保存。测试已保存连接会发出真实 API 请求，可能产生费用。

| 服务商             | API 域名                            |
| ------------------ | ----------------------------------- |
| OpenAI             | `api.openai.com`                    |
| DeepSeek           | `api.deepseek.com`                  |
| Google Gemini      | `generativelanguage.googleapis.com` |
| Claude / Anthropic | `api.anthropic.com`                 |

每个服务商独立保存 Key、模型和授权。切换服务商后保存才会更新当前配置。
项目不提供模型订阅或 PageCraft 代理服务器。模型 ID 由用户填写，支持某个服务商
不代表兼容该服务商的所有模型。

**界面语言**在“通用设置”中配置，与 AI 配置无关。跟随浏览器时，中文语言环境
使用简体中文，其他语言使用英文。切换语言保留正在编辑的内容，不自动翻译用户
内容和 AI 输出。浏览器扩展名称和工具栏标题跟随 Chrome 语言，而非应用内选项。

## 使用网页改造

1. 在“当前页面”描述新增改造，或选中已有改造继续优化。
2. 需要时采集页面摘要、选择元素并检查上下文；未提供上下文时，生成流程会自动采集。
3. 检查应用范围，点击“生成并应用”，按提示授予网站权限。
4. 检查效果，通过“我的改造”编辑源码、停用、删除或回退版本。

当前页面展示已有功能与最近一次操作，不展示完整对话记录；内部仍可能使用同一
改造的近期需求作为上下文。AI 修订保持改造名称不变，名称需在编辑页手动修改。

匹配规则示例：

```text
https://example.com/*
https://*.example.com/articles/*
```

规则匹配协议、主机名和路径，不要填写端口、查询参数或 fragment。匹配时忽略
查询参数和 fragment，排除规则优先；包含与排除规则合计最多 30 条。

## 自建工具

进入“工具 → 创建工具”，使用自然语言生成或手动编写。AI 生成只填充编辑器草稿，
不会自动保存或运行。进入编辑器时需求为空，生成成功后清空，不回填历史需求。
“试运行”会真实执行代码，检查效果后再保存。

JavaScript 编辑器接受**异步函数体**，可以直接使用 `await` 和 `return`，不需要外层函数：

```js
const links = [...document.querySelectorAll('a[href]')];
return {
  kind: 'table',
  columns: ['标题', '链接'],
  rows: links
    .slice(0, ctx.params.limit ?? 100)
    .map((link) => [(link.textContent ?? '').trim(), link.href]),
  filename: 'links.csv',
};
```

运行参数必须是 JSON 对象，例如 `{"limit": 100}`。

| 接口                                         | 用途                                   |
| -------------------------------------------- | -------------------------------------- |
| `ctx.params`                                 | 已保存的默认运行参数                   |
| `ctx.signal`                                 | 协作式取消信号                         |
| `ctx.onCleanup(fn)`                          | 注册生命周期清理函数                   |
| `ctx.tools.screenshot({ fullPage: false })`  | 可视区域截图；传 `true` 请求整页截图   |
| `ctx.tools.extractText()`                    | 提取页面文本                           |
| `ctx.tools.download(result)`                 | 请求下载；手动和自动模式的触发方式不同 |
| `ctx.ai.ask({ instruction, input, signal })` | 调用已配置模型并返回文本               |

手动运行支持字符串、文本、表格、图片和文本文件结果。结果只临时保留，不是
持久化运行记录；工具代码、参数、自动启动配置和最近 10 个版本保存在本机。

自动工具需要明确启用并授予范围权限，保存后可立即在已打开的匹配页面运行。
自动实例持续到生命周期结束，返回值不会展示在扩展的结果预览中。创建 DOM、
事件监听等资源时应注册清理函数。自动工具中的 AI 调用可能无需再次点击工具栏
就产生费用，应设计为用户明确操作后再请求。

完整生命周期、返回格式和示例见 [自定义工具接口](docs/CUSTOM_TOOLS.md) 和
[运行时 AI](docs/RUNTIME_AI.md)。自建工具的 `ctx` 接口与
[网页改造运行器](docs/RUNTIME.md) 不可直接混用。

## 数据与权限

- 设置、Key、改造、工具及版本存入本机扩展存储；改造对话草稿和上下文使用浏览器会话存储。项目没有内置云同步、账号系统或遥测后台。
- 生成时向所选服务商发送需求、相关旧代码及适用的页面上下文。自建工具生成仅在勾选时附带页面摘要；运行时 AI 发送工具明确提供的 `instruction` 和 `input`。
- 摘要采集器跳过表单控件、可编辑内容、隐藏内容和脚本/样式，移除 URL 查询参数与 fragment。可见文本、标题、ID 和类名仍可能含有敏感信息，不等同于匿名化保证。
- 内置截图本地处理，本身不调用 AI；截图可能包含可见表单值和个人信息。自建代码可独立收集数据或联系外部服务。
- API Key 由后台使用，不传给生成脚本；本机存储不等同于加密保险库。

| 权限                     | 用途                                       |
| ------------------------ | ------------------------------------------ |
| `storage`                | 偏好、已保存内容、任务与会话状态           |
| `sidePanel`              | 侧边栏界面                                 |
| `tabs`                   | 目标标签信息与生命周期处理                 |
| `activeTab`、`scripting` | 截图、页面上下文、元素选择及页面侧操作     |
| `userScripts`            | 执行改造与自建工具                         |
| `alarms`                 | 撤销期限后清理已删除改造                   |
| 服务商主机权限           | 请求已支持服务商的 API                     |
| 可选网站权限             | 用户授权的网站访问、自动工具和截图备用授权 |

## 限制与排查

- **脚本不生效：** 检查“允许用户脚本”、网站权限、匹配规则和页面类型。浏览器内部页、商店页和 PDF 不是普通改造目标。
- **整页截图失败：** 合并画布单边最多 32,760 像素，总面积最多 3200 万像素。无限滚动、页面尺寸变化、无法滚动等情况可能需要可视区域截图。
- **截图被停止：** 切换活动标签、刷新或替换文档会停止普通页面截图；仅同一文档 URL 改变不会停止。受保护商店页使用更保守的检查。
- **Chrome 扩展商店截图：** 不支持整页截图；临时 `activeTab` 授权后可能支持可视区域截图。所有网站授权不能绕过受保护页面限制。
- **超时：** 代码生成最多 4 分钟，手动自建工具运行和单次运行时 AI 请求最多 2 分钟。自动实例不受手动运行的生命周期时限限制。
- **取消与回退：** 已发送请求、已提交表单和任意 DOM 修改不保证可撤销。协作式取消不能强制终止同步死循环。

## 开发与测试

### 本地开发流程

1. 使用 `npm ci` 安装依赖。
2. 使用 `npm run dev` 开发界面，使用 `npm run build` 构建可加载的扩展。
3. 在 Chrome 加载 `dist/`；修改后重新构建并重新加载扩展。
4. 提交变更前运行相关测试并检查格式。

| 命令                   | 用途                                       |
| ---------------------- | ------------------------------------------ |
| `npm run dev`          | Vite 界面预览，以终端输出地址为准          |
| `npm run build`        | 类型检查、界面构建及后台打包，输出 `dist/` |
| `npm test`             | 单元测试，包括语言回退和静态翻译覆盖       |
| `npm run test:e2e`     | 使用模拟 AI 的 Chromium 扩展回归测试       |
| `npm run format:check` | 检查源码格式                               |
| `npm run format`       | 格式化源码                                 |

首次运行浏览器测试前安装 Chromium：

```sh
npx playwright install chromium
npm test
npm run test:e2e
```

普通网页预览不能访问扩展 API，完整验证需加载扩展。浏览器测试使用临时配置目录
和预授权的扩展副本，不修改分发用 manifest。测试不验证真实服务商生成质量，
也不能代替原生授权弹窗的人工验收。

### 架构概览

React 界面收集需求、管理已保存内容；后台 service worker 调用 AI 服务商、协调权限
与任务并注册脚本。改造和自建工具通过 Chrome 用户脚本 API 操作目标网页，
两者使用不同的运行时接口。已保存内容和服务商设置存入扩展存储，不需要 PageCraft 后端。

```text
弹窗 / 侧边栏 / 管理页
          |
    后台 Service Worker ----> 选定的 AI 服务商
          |
    改造与工具运行时 --------> 目标网页
          |
    Chrome 扩展存储
```

### 源码导航

```text
src/main.tsx                  导航、改造管理、设置
src/CurrentPage.tsx           当前页面改造流程
src/worker.ts                后台消息、生成和脚本注册
src/ai.ts, src/providers.ts   服务商请求和配置
src/context.ts               页面摘要和元素选择
src/runtime.ts, src/rules.ts  改造生命周期及网址匹配
src/store.ts                 串行存储事务
src/check.ts                 语法与生成结果结构校验
src/tools/                   截图、自建工具、自动启动及运行时 AI
src/i18n.ts, src/locales/     界面国际化
public/manifest.json         扩展权限和入口
public/_locales/             Chrome 原生本地化元数据
tests/, scripts/e2e.mjs      单元和浏览器测试
```

## 参与贡献

欢迎反馈问题、完善文档、翻译界面、补充测试和提交聚焦的代码改进。提交代码前，
提交的贡献采用本项目的 [MIT 许可证](LICENSE)。

较大功能建议先通过 Issue 讨论使用场景和范围。小型修复可以按以下流程进行：

1. 在本地仓库或 Fork 中创建分支。
2. 保持修改范围集中，沿用现有 TypeScript 与界面设计模式。
3. 为行为变化增加或更新测试。用户文档变化同步更新中英文 README；新增界面文本同时提供中英文翻译。
4. 运行 `npm test`、`npm run build` 和 `npm run format:check`。涉及扩展运行时或界面时，还需运行 `npm run test:e2e`，并在 Chrome 中手动验证受影响流程。
5. 创建 Pull Request，说明问题、修改内容和验证结果。界面调整附截图；权限变化或发送给服务商的数据变化需明确说明。

不要提交 API Key、`.env`、私人网页内容、浏览器配置目录、生成的 `dist/` 或本地
测试产物。测试应使用合成样例与模拟 AI，不依赖贡献者的付费 API 账号。
